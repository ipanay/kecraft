# KECRAFT · kecraft.com

面向消费者的非标手机壳定制平台。消费者在网页上选择已验证的机型，并以可视化方式描述自己的特殊需求；设计师在本地复核参数、生成或微调 STL，并使用 3D 打印完成制作。

> 域名：kecraft.com

## 项目背景

项目源自已有的 3D 打印手机壳定制业务。典型客户包括：

- 使用改装电池、散热模块、镜头附件或 MagSafe 配件的用户；
- 市面上没有现成壳，或原装壳价格过高的冷门机型用户；
- 需要自定义开孔、避让、文字或固定结构的用户。

当前人工流程为：客户提供机型与需求，设计师在 MakerWorld 国际区、国内区等 3D 社区检索手机壳模型，参考下载量、评价和评论筛选可靠模型；再从模型反推结构、按客户需求修改、布尔处理并打印。

本项目的目标不是把这套流程简单搬到网页，而是逐步将实践经验沉淀为可复用的机型、参数和 PETG 设计规则。

## 产品原则

1. **消费者不接触 STL。** 消费者只看到设计预览、关键尺寸和确认图；STL 由设计师在本地完成最终复核和微调。
2. **已验证机型优先。** 首版只开放已用模型机或实物验证过的机型，降低适配风险。
3. **拖拽优先，数值兜底。** 普通用户通过 2D/3D 可视化拖拽完成定位；所有操作同步为毫米数值，供高级调整与设计师复核。
4. **不让消费者测量整台手机。** 标准手机结构由机型档案锁定；消费者只需描述或测量自己独有的改装附件。
5. **制造规则可追溯。** 每次生成的设计都应能回溯到机型版本、壳体规则、用户操作和人工调整。

## 当前制造前提

- 主要材料：PETG。
- 生产方式：本地 3D 打印。
- 机型验证方式：优先购买模型机并实测/试装。
- 社区模型用途：作为适配结构参考、数据校验和经验来源；长期目标是生成自己的参数化壳体，而非直接向消费者交付社区 STL。

## 首版目标

先验证消费者在电脑端的操作体验，而不是立即做完整电商、AI 或 STL 系统。

### 包含

- 已验证机型列表与机型详情；
- 单个示例机型的 3D 壳体预览；
- 背面与四侧的 2D 正投影视图；
- 可拖拽的定制模块占位区；
- 散热模块、MagSafe、改装电池、开孔、文字等需求入口；
- 实时显示位置、宽高、深度等参数；
- PETG 规则提示：壳厚、最小壁厚、孔间距和碰撞风险；
- 生成消费者确认用的设计图与参数摘要。

### 暂不包含

- 账号、支付、订单履约；
- 自动调用 AI 检索手机官网数据；
- 自动抓取或下载 3D 社区模型；
- 真实在线 STL 导出；
- 手机端完整 3D 编辑；
- 图案编辑与图片上传定制。

## 消费者流程

```text
选择已验证机型
  → 确认具体版本
  → 选择特殊需求
  → 在电脑端进入精细编辑
  → 在正投影视图拖拽模块/开孔
  → 在 3D 视图确认整体效果
  → 查看设计图与风险提示
  → 提交设计申请
  → 设计师本地复核、微调 STL、打印
```

手机端适合浏览、选择机型、填写说明、上传参考图和查看确认图；精细 3D 操作优先在电脑端完成。

## 编辑器交互

编辑器采用“2D 精确编辑 + 3D 整体确认”的模式：

- **2D 正投影视图**：背面、左侧、右侧、顶部、底部，带毫米网格、边缘标尺和吸附线；这是主要编辑面。
- **3D 预览**：用于查看壳厚、凸起、避让与碰撞关系。
- **受限拖拽**：侧边按键只能沿侧边移动，充电口只能沿底边移动，背部模块只能在背面移动，减少误操作。
- **参数联动**：拖动后自动更新距离、宽高、深度等数值；用户也可直接输入数值。
- **打印安全检查**：检查最小壁厚、孔间距、镜头区距离、部件碰撞和可制造性。

## 机型档案

每个机型应形成一份可复用档案：

- 品牌、型号、地区/运营商版本；
- 官方外形数据与数据来源；
- 模型机/实物验证状态；
- 镜头、按键、接口、扬声器等结构数据；
- 参考社区模型的来源、版本、许可和筛选备注；
- PETG 公差、壳厚、圆角、包边、开孔等规则；
- 特殊机型偏移或历史适配问题；
- 已打印验证记录与设计师备注。

机型状态建议分为：

- **已实物验证**：可直接开放消费者自助定制；
- **资料待验证**：可接受定制申请，但须人工确认；
- **暂不支持**：尚无可靠基础资料或模型。

## 长期技术方向

长期目标是搭建参数化壳体生成器：

```text
手机官网/可靠资料 + 已验证结构经验
  → 手机本体与关键结构参数
  → PETG 公差与机型特例规则
  → 参数化壳体模型
  → 用户定制操作（开孔、避让、文字、固定结构）
  → 设计师复核与本地 STL 输出
```

社区模型的价值在于帮助校验官方数据、学习适配结构和积累规则；每个成功订单都应反哺到规则库与机型档案中。

## 设计稿

当前已完成两种桌面端交互方向：

- **工作台式**：适合熟悉需求、直接进行精细拖拽的用户；
- **引导式**：先以简单问题收集特殊需求，再进入工作台精细编辑。

后续需根据反馈确认一种主流程，再进入真实前端原型开发。
